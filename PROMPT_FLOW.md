Documentation research was used to avoid inventing provider credentials, endpoint paths, or AQI calculations.

## Architecture decisions

- Keep provider credentials and all external API requests on the server.
- Treat CPCB as the only source for the official AQI display.
- Never calculate an Indian AQI from pollutant-only readings.
- Keep OpenAQ raw measurements in a separate section with source attribution.
- Return unavailable, stale, or unverified states instead of fabricating values or substituting locations.
- Keep preferences in localStorage for the no-login first version; Supabase can be added later.
- Use a replaceable Gemini adapter and provide a clear configuration response when no key is set.
- Add a shared typed provider contract before building the dashboard UI.

### Decisions made during implementation

- The generic OGD resource endpoint and API-key query authentication are implemented, but no CPCB resource UUID is hardcoded. The official catalog page retrieved during this iteration exposed only partial field metadata, and the authenticated response schema could not be verified without the missing resource ID and key.
- CPCB AQI is accepted only from an explicit `aqi` or `AQI` field at the selected station's latest observation timestamp. Pollutant-only records remain raw pollutant observations; they never generate an AQI. Location matching uses normalized exact city matching and, when coordinates are supplied, a coordinate-bearing station within 50 km.
- OpenAQ uses the documented `X-API-Key` header and v3 locations, location sensors, and location latest endpoints. One nearest Indian monitor is selected within 25 km. Values stay tied to that location and each sensor keeps its own timestamp and freshness; values are not averaged across stations or times.
- Gemini receives the selected location, current source payloads and statuses, recent conversation, and validated lifestyle preferences. The provider requests structured JSON, validates it with Zod, checks its evidence tags against available data, and rejects generated AQI/pollutant numbers, timestamps, station claims, unsupported category claims, and numeric environmental claims. Verified source context is formatted separately by the server.
- Recommendation cards are generated from validated local rules. Only a live explicit CPCB AQI can drive category-sensitive current recommendations; profile fields shape the intended audience and commute alternatives.
